# Frontend Architecture

Next.js 16.0.3 App Router application in [`frontend/`](../../frontend/) — 96 files: **26 pages,
29 route handlers, 12 components, 2 hooks, 4 utils, 2 lib**.

## Route groups carry no behaviour

`(auth)` and `(main)` are Next.js route groups — parentheses exclude the segment from the URL.

- **No `middleware.ts` anywhere.**
- Only one layout, `app/layout.tsx`.
- No route guard, no redirect for unauthenticated visitors.

A page under `(auth)` is exactly as public as one under `(main)`. Protection exists only inside the API
handlers that read the session cookie, so pages render and then fail to populate.
[AUDIT.md](../../AUDIT.md) issue 4.

## The BFF layer

All 29 handlers follow the same shape: read the request, attach headers server-side, forward to
FastAPI, return the payload.

```ts
const cookieStore = await cookies();
const token = cookieStore.get("session_token")?.value;

const { data } = await axios.post(
  `${API_URL.replace(/\/$/, "")}/master/feature/list`,
  body,
  { headers: { "PK-apiToken": API_TOKEN, "PK-sessionToken": token } }
);
```

Both `fetch` and `axios` are used. URL construction is inconsistent — most handlers normalise with
`.replace(/\/$/, "")`, a few concatenate directly, and `user-list` does neither and double-slashes.

> **Only 12 of the 29 handlers reach a live backend endpoint.** Four omit a `user/` prefix, five target
> commented-out routers, seven have no backend at all. Full table:
> [../api/frontend-contract-map.md](../api/frontend-contract-map.md).

## Session handling

```
POST /api/login
  → POST {API_URL}user/login
  → read Success.data.session_token and Success.data.username
  → res.cookies.set("session_token", token, {
        httpOnly: true, secure: true, sameSite: "lax", path: "/", maxAge: 60*60*24*7 })
  → res.cookies.set("username", username, { httpOnly: false, ... })
```

The session token is correctly inaccessible to client JavaScript. `username` is deliberately readable —
`DashboardLayout` parses it from `document.cookie` to greet the user.

Three defects in this flow:

| # | Defect |
| - | ------ |
| F3 | `login/route.ts` computes `const encryptedToken = encrypt(token)` via `utils/crypto.ts`, then stores the **raw** token. The encrypted value is discarded |
| F1 | `logout/route.ts` builds an axios config targeting `${API_URL}logout` and **never executes it** — the backend session is never invalidated |
| F2 | Logout deletes a `user_email` cookie; login sets `username`. The username cookie survives logout |

## Google OAuth

```
GET /api/google           → redirect to accounts.google.com/o/oauth2/v2/auth
                            scope "openid email profile", prompt=select_account
GET /api/google/callback  → POST oauth2.googleapis.com/token      (code → access_token)
                          → GET  googleapis.com/oauth2/v2/userinfo
                          → POST {API_URL}user/login-email        (backend issues session)
                          → set session_token cookie
```

Reads `process.env.CLIENT_ID`, `CLIENT_SECRET`, `REDIRECT_URI` directly — **not** the
`GOOGLE_CLIENT_ID` / `GOOGLE_REDIRECT_URI` constants exported from `utils/api.ts`, which are unused.

## State management

None in the library sense. Every page is a `"use client"` component using `useState`, `useEffect`,
`useRef`. No Redux, Zustand, React Query or Context provider. `zod` and `react-hook-form` are **not
dependencies** here — forms are manually controlled and validated inline.

## Notable page-level findings

- `search-excel` and `employee/search-employee-doc` are **byte-identical stubs** embedding an iframe at
  `http://localhost:8000` — the FastAPI port, not a Chainlit server — both titled "PolicyForYou AI".
- `settings` is a 13-line stub containing only a heading.
- `excel-list` calls `/api/query/RES-1001` and `/api/query/RES-1002` — handlers that do not exist, with
  hard-coded IDs.
- `employee/upload-employee-doc` calls `/api/employee-document/` — also non-existent.
- `Analytics` (246 lines) renders Recharts visualisations over local state with no API call.
